Source code: Lib/token.py
This module provides constants which represent the numeric values of leaf nodes
of the parse tree (terminal tokens).  Refer to the file Grammar/Tokens
in the Python distribution for the definitions of the names in the context of
the language grammar.  The specific numeric values which the names map to may
change between Python versions.
The module also provides a mapping from numeric codes to names and some functions. The functions mirror definitions in the Python C header files.
Note that a tokenâs value may depend on tokenizer options. For example, a
"+" token may be reported as either PLUS or OP, or
a "match" token may be either NAME or SOFT_KEYWORD.

The token constants are:
- token.NAMEÂ¶
- Token value that indicates an identifier or keyword.
- token.NUMBERÂ¶
- Token value that indicates a numeric literal
- token.STRINGÂ¶
- Token value that indicates a string or byte literal, excluding formatted string literals. The token string is not interpreted: it includes the surrounding quotation marks and the prefix (if given); backslashes are included literally, without processing escape sequences.
- token.OPÂ¶
- A generic token value that indicates an operator or delimiter. CPython implementation detail: This value is only reported by the tokenize module.
Internally, the tokenizer uses
exact token types instead.
- token.COMMENTÂ¶
- Token value used to indicate a comment. The parser ignores COMMENT tokens.
- token.NEWLINEÂ¶
- Token value that indicates the end of a logical line.
- token.NLÂ¶
- Token value used to indicate a non-terminating newline. NL tokens are generated when a logical line of code is continued
over multiple physical lines. The parser ignoresNL tokens.
- token.INDENTÂ¶
- Token value used at the beginning of a logical line to indicate the start of an indented block.
- token.DEDENTÂ¶
- Token value used at the beginning of a logical line to indicate the end of an indented block.
- token.FSTRING_STARTÂ¶
- Token value used to indicate the beginning of an f-string literal. CPython implementation detail: The token string includes the prefix and the opening quote(s), but none of the contents of the literal.
- token.FSTRING_MIDDLEÂ¶
- Token value used for literal text inside an f-string literal, including format specifications. CPython implementation detail: Replacement fields (that is, the non-literal parts of f-strings) use the same tokens as other expressions, and are delimited by LBRACE ,RBRACE ,EXCLAMATION andCOLON tokens.
- token.FSTRING_ENDÂ¶
- Token value used to indicate the end of a f-string. CPython implementation detail: The token string contains the closing quote(s).
- token.TSTRING_STARTÂ¶
- Token value used to indicate the beginning of a template string literal. CPython implementation detail: The token string includes the prefix and the opening quote(s), but none of the contents of the literal. Added in version 3.14.
- token.TSTRING_MIDDLEÂ¶
- Token value used for literal text inside a template string literal including format specifications. CPython implementation detail: Replacement fields (that is, the non-literal parts of t-strings) use the same tokens as other expressions, and are delimited by LBRACE ,RBRACE ,EXCLAMATION andCOLON tokens.Added in version 3.14.
- token.TSTRING_ENDÂ¶
- Token value used to indicate the end of a template string literal. CPython implementation detail: The token string contains the closing quote(s). Added in version 3.14.
- token.ENDMARKERÂ¶
- Token value that indicates the end of input. Used in top-level grammar rules.
- token.ENCODINGÂ¶
- Token value that indicates the encoding used to decode the source bytes into text. The first token returned by tokenize.tokenize() will
always be anENCODING token.CPython implementation detail: This token type isnât used by the C tokenizer but is needed for the tokenize module.
The following token types are not produced by the tokenize module,
and are defined for special uses in the tokenizer or parser:
- token.TYPE_IGNOREÂ¶
- Token value indicating that a type: ignore comment was recognized.
Such tokens are produced instead of regularCOMMENT tokens only
with thePyCF_TYPE_COMMENTS flag.
- token.TYPE_COMMENTÂ¶
- Token value indicating that a type comment was recognized. Such tokens are produced instead of regular COMMENT tokens only
with thePyCF_TYPE_COMMENTS flag.
- token.SOFT_KEYWORDÂ¶
- Token value indicating a soft keyword. The tokenizer never produces this value. To check for a soft keyword, pass a NAME tokenâs string tokeyword.issoftkeyword() .
- token.ERRORTOKENÂ¶
- Token value used to indicate wrong input. The tokenize module generally indicates errors by
raising exceptions instead of emitting this token.
It can also emit tokens such asOP orNAME with strings that
are later rejected by the parser.
The remaining tokens represent specific operators and
delimiters.
(The tokenize module reports these as OP; see exact_type
in the tokenize documentation for details.)
